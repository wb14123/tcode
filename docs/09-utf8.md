# UTF-8 support

tcode is a UTF-8-only system end to end: conversation data, file contents, file paths, and
command output are all handled as UTF-8.

- LLM APIs exchange JSON over HTTP with `charset=utf-8`, so non-UTF-8 bytes cannot be sent to a
  model.
- The `read`, `glob`, `grep`, and `bash` tools decode their input as UTF-8.
- Streaming responses (SSE) are accumulated as raw bytes and decoded only per complete line, so
  a multi-byte character split across network chunks (e.g. Chinese text) round-trips correctly.

Non-UTF-8 data is never silently mangled — no U+FFFD replacement characters are substituted into
results. Instead, tcode fails loudly or reports the omission:

## Files that are not valid UTF-8 (`read` tool)

- Invalid bytes **within** the displayed portion of a file: the read fails with an error naming
  the file, the line, and the byte offset of the first invalid byte, plus a hint — inspect the
  raw bytes by re-reading the file through `base64`, or ask the user about the file's encoding.
- Invalid bytes **beyond** the `max_read_chars` display budget (they would never be shown): the
  line is truncated at the budget and the read continues — the valid portion is returned instead
  of an error.

## Command output that is not valid UTF-8 (`bash` tool)

The command fails with an error explaining that the output was omitted and how to inspect it
(re-run piped through `base64`).

## Paths that are not valid UTF-8

A file or directory name that is not valid UTF-8 cannot be converted to a string:

- Where correctness matters — permission keys, lock file names, command arguments — the
  operation fails loudly and the error shows the raw bytes via Rust Debug escaping (e.g.
  `\xff`).
- Search and listing tools (`glob`, `grep`, directory listing) **skip** non-UTF-8 entries and
  append a count note to the result (e.g. `(2 file(s) with non-UTF-8 paths were omitted from the
  results.)`), so the result's incompleteness is visible.

## Recommendation

Keep files, paths, and command output in UTF-8. Other encodings (GBK, Shift-JIS, ISO-8859-1,
UTF-16, ...) are not supported — convert them first, e.g.:

```sh
iconv -f GBK -t UTF-8 input.txt > output.txt
```
